## 1.1 기획 개요

### 1.1.1 프로젝트 배경 및 목적
- A/S 업체가 고객 정보 관리부터 수리 접수, 기사 배정, 수리비 산정, 입금 확인, 배송 및 운영 통계까지의 업무를 하나의 시스템에서 처리할 수 있는 **통합 A/S 업무 관리 플랫폼** 구축.
- 전화, 이메일 및 방문을 통해 접수되는 고객의 A/S 요청을 체계적으로 관리하고, 수기 장부와 엑셀 중심의 분산된 업무 환경을 디지털화하여 운영 효율성 향상.
- 접수 대기부터 수리, 입금, 배송 완료까지 A/S 업무의 전체 생명 주기를 표준화하고, 담당자와 상태 변경 이력을 관리하여 업무 누락 및 처리 지연 방지.
- Spring Boot와 Spring Data JPA 기반의 백엔드 시스템과 React 기반 SPA 클라이언트를 RESTful API로 연동하여 역할 별 업무 환경 제공.
- 토스페이먼츠 테스트 가상계좌, 외부 SMS 발송 API 및 모의 배송 웹훅을 연동하여 실제 업무 환경에서 발생하는 외부 시스템 통신, 비동기 이벤트 처리 및 데이터 정합성 관리 구현.
- Docker 및 Github Action 기반의 CI/CD 환경을 구축하여 팀 단위 개발, 테스트 및 배포 프로세스 자동화.

### 1.1.2 서비스 핵심 가치
- **A/S 업무지원:** A/S 업체가 고객, 직원, 수리 및 결제 데이터를 독립적으로 관리하는 업무 환경 제공.
- **역할 기반 접근 제어(RBAC):** 관리자(ADMIN), 접수 담당자(RECEPTIONIST), 수리 기사(TECHNICIAN)의 역할을 분리하여 업무별 접근 권한 제어.
- **직원 중심 A/S 접수:** 고객이 별도 회원가입이나 로그인 없이 전화·이메일·방문으로 수리를 요청하면 업체 직원이 시스템에 접수하는 업무 구조 제공.
- **표준화 된 A/S 처리 프로세스:** 접수, 기사 배정, 수리 작업, 비용 확정, 입금 확인 및 배송 완료까지 일관된 업무 흐름 제공.
- **수리 이력 및 비용 관리:** 고객과 제품을 기준으로 과거 수리 이력을 조회하고, 표준 수리 항목을 활용하여 수리비를 자동 계산.
- **안정적인 입금 처리:** PG 가상계좌 발급 및 입금 웹훅 연동을 통해 입금 상태를 자동 반영하고 중복 이벤트 처리로 인한 데이터 불일치 방지.
- **업무 자동화 및 알림:** 주요 A/S 상태 변경 시 SMS 알림을 발송하고 배송 이벤트를 연계하여 반복적인 수동 업무 감소.
- **업체 운영 가시성 확보:** 관리자에게 접수, 수리, 미입금, 배송 및 완료 현황을 제공하여 운영 상태를 효율적으로 파악.

### 1.1.3 기대 효과
- 전화·이메일 기반 A/S 접수 정보의 중앙 집중화를 통한 업무 누락 및 중복 접수 감소.
- 고객 정보와 수리 이력의 통합 관리를 통한 반복 고객 응대 및 이력 조회 효율성 향상.
- 기사 배정과 수리 상태의 체계적 관리를 통한 업무 처리 시간 단축.
- 표준 수리 항목 및 자동 비용 계산을 통한 수리비 산정 오류 감소.
- 가상계좌 입금 확인 및 배송 상태 연계를 통한 수작업 감소와 업무 정합성 향상.
- 대시보드 및 통계 제공을 통한 운영 현황 분석과 업무 의사결정 지원.
- RBAC, 트랜잭션, 동시성 제어 및 웹훅 멱등성 등 실무 중심 백엔드 기술 역량 확보.

## 1.2 주요 기능 요구사항

### 1.2.1 회원 및 다중 역할 인증 관리 (Auth & Member)

- **관리자 기반 계정 발급:** 일반 회원가입을 제공하지 않으며, 관리자가 소속 직원 계정을 생성.
- **관리자 초기 계정 구성:** 시스템 초기 실행 시 ADMIN 계정을 초기 데이터 또는 환경 설정을 통해 생성.
- **보안 인증 체계:** Spring Security와 JWT 기반 인증을 적용하여 사용자 로그인 및 API 접근 제어.
- **역할 기반 접근 제어(RBAC):** ADMIN, RECEPTIONIST, TECHNICIAN 역할 별 업무 권한 관리.
- **관리자에 의한 역할 별 권한 수정:** 각 역할 별 세부 권한을 관리자가 수정 가능 
- **직원 복수 역할 지원:** 한 직원이 접수 담당자와 수리 기사 역할을 동시에 수행할 수 있도록 다중 역할 부여 지원.
- **직원 계정 관리:** 관리자가 직원 계정을 등록·수정·비활성화하고 역할을 부여하거나 변경.
- **내 계정 정보 관리:** 사용자 본인의 이름, 연락처, 비밀번호 등 기본 정보 조회 및 수정.
- **계정 보안 관리:** 비밀번호 해시 저장, 인증 실패 처리 및 권한 없는 API 요청 차단.

### 1.2.2 고객 및 고객 정보 관리 (Customer Management)

- **고객 정보 CRUD:** 고객명, 연락처, 이메일, 주소 및 비고 등의 기본 정보를 등록·조회·수정·삭제 또는 비활성화.
- **고객 목록 검색 및 필터링:** 고객명, 연락처, 고객 유형 및 등록일을 기준으로 고객 검색.
- **고객 엑셀 일괄등록:** 기존 엑셀 파일의 고객 데이터를 일괄 업로드하여 시스템에 등록.
- **고객 데이터 엑셀 문서화:** 등록된 고객 정보를 엑셀 문서로 다운로드.
- **엑셀 데이터 검증:** 필수값, 연락처 형식, 고객 유형 및 중복 데이터 등을 검증하고 등록 성공·실패 결과 제공.
- **고객 중복 등록 방지:** 동일 업체 내 기존 고객의 연락처 및 식별 정보를 확인하여 중복 등록 위험 안내.
- **고객별 A/S 이력 조회:** 고객 상세 화면에서 해당 고객의 과거 A/S 접수, 수리 내역 및 진행 상태 조회.
- **고객 정보 자동 입력:** 기존 고객을 선택하여 A/S 요청을 등록하면 고객 연락처 및 주소 등 기본 정보 자동 입력.
- **고객 개인정보 보호:** 연락처, 주소 등 개인정보에 대한 접근 권한 검증 및 필요 시 마스킹 처리.

### 1.2.4 제품 및 수리 대상 관리 (Product Management)

- **제품 모델 등록 및 관리:** A/S 업체가 수리하는 제품의 제조사, 제품명, 모델명, 제품 분류 및 비고 등록.
- **제품 모델 목록 조회:** 제조사, 제품 분류, 모델명 및 사용 상태를 기준으로 제품 모델 검색.
- **수리 대상 제품 정보 등록:** A/S 접수 시 제품 모델, 시리얼번호, 고장 증상 및 기타 식별 정보 입력.
- **시리얼번호 기반 제품 식별:** 제품에 시리얼번호가 존재하는 경우 이를 기록하여 동일 제품의 과거 수리 이력 조회에 활용.
- **시리얼번호 미확인 제품 수리 불가:** 시리얼번호가 없거나 확인되지 않는 제품은 접수 불가.
- **고객별 수리 제품 이력 조회:** AS접수 화면에서 고객이 과거에 맡긴 제품과 수리 내역을 조회하여 재접수 시 활용.
- **제품 정보 자동 입력:** 기존 제품 정보를 선택하거나 이전 접수 정보를 참조하여 신규 A/S 접수 시 반복 입력 최소화.

### 1.2.5 A/S 요청 및 접수 관리 (A/S Request & Reception)

- **전화·이메일·방문 A/S 접수:** 접수 담당자가 고객의 요청을 확인한 후 고객, 제품, 고장 증상, 담당 기사 및 접수 내용을 시스템에 등록.
- **기존 고객 검색 및 신규 고객 등록:** A/S 접수 시 기존 고객을 검색하여 선택하거나 신규 고객 정보를 등록.
- **개인·기업 고객 공통 접수:** 고객 유형과 관계없이 동일한 A/S 접수 프로세스를 적용하며 기업 고객은 기업 정보를 함께 기록.
- **접수 경로 관리:** 전화, 이메일, 방문 등 A/S 요청이 접수된 경로를 기록.
- **접수번호 자동 발급:** 신규 A/S 요청 등록 시 고유 접수번호를 생성하여 이후 업무 조회 및 처리에 활용.
- **제품 및 고장 정보 등록:** 제품명, 모델명, 시리얼번호, 고장 증상, 고객 요청 사항 및 접수 메모 입력.
- **고장증상 프리셋화:** AS 접수 시 프리셋에 등록된 주요 고장 증상들을 다중 선택 / 프리셋에 없는 증상은 별도 메모창에 입력 
- **A/S 요청 목록 및 상세 조회:** 접수번호, 고객명, 제품 모델, 접수일, 담당 기사 및 진행 상태를 기준으로 검색.
- **A/S 요청 수정 및 취소:** 접수 진행 상태에 따라 허용된 항목을 수정하거나 접수 취소 처리.
- **배송 및 수령 정보 등록:** 수리 완료 후 제품 반환에 필요한 수령인, 연락처, 배송지 및 반환 방식 정보 관리.
- **고객별 접수 이력 조회:** 고객의 과거 A/S 요청 및 수리 결과를 확인하여 반복 고장 여부 파악.
- **접수 SMS 연계:** A/S 접수 등록 또는 승인 시 고객 연락처로 접수번호 및 진행 안내 SMS 발송.

### 1.2.6 A/S 기사 배정 및 상태 관리 (Assignment & Workflow)

- **접수된 업무 목록 관리:** 접수 담당자가 업체에 접수된 A/S 요청을 조회.
- **기사 배정 변경:** 담당 기사의 부재나 업무 조정 시 다른 기사로 변경하고 배정 이력 기록.
- **기사별 담당 업무 조회:** 수리 기사가 자신에게 배정된 A/S 요청 및 진행 상태 조회.
- **A/S 상태 전이 관리:** 접수 → 수리 중 → 입금대기 → 배송대기 → 완료의 표준 업무 흐름 적용.
- **상태 변경 조건 검증:** 현재 상태와 선행 업무 완료 여부를 확인하여 허용되지 않은 상태 변경 차단.
- **수리 작업 시작 연계:** 담당 수리 기사가 작업을 시작하면 수리 시작 버튼을 눌러 A/S 상태를 수리 중으로 변경.
- **수리 불가 판정** 수리기사가 수리 불가 판정을 할 경우 해당 사유 입력 및 수리 불가 버튼을 눌러 A/S 상태를 수리 불가로 변경
- **수리비 확정 연계:** 수리 작업 완료 후 수리비가 확정되면 수리 완료 버튼을 눌러 A/S 상태를 입금대기로 변경.
- **입금 완료 연계:** 결제 도메인에서 입금 완료가 확인되면 배송대기 상태로 변경.
- **배송 완료 연계:** 제품 배송 완료 또는 반환 완료가 확인되면 A/S 상태를 완료로 변경.
- **상태 변경 이력 관리:** 상태 변경 전후 값, 변경자, 변경 일시 및 변경 사유 기록.
- **장기 미처리 업무 조회:** 일정 기간 이상 접수대기 또는 수리 중 상태로 유지된 A/S 요청을 조회.

### 1.2.7 수리 작업 및 비용 관리 (Repair & Cost)

- **수리 작업 시작 및 기록:** 담당 수리 기사가 작업 시작 후 고장 원인, 점검 결과, 수리 내용 및 작업 메모 등록.
- **수리 항목 프리셋 관리:** 관리자가 자주 수행하는 수리 작업 항목과 기본 수리비를 등록·수정·비활성화.
- **수리 항목 선택 및 적용:** 담당 수리 기사가 사전에 등록된 수리 항목을 선택하여 수리 내역에 추가.
- **수리 항목 수동 등록:** 프리셋에 없는 수리 작업은 항목명, 설명, 단가 및 수량을 직접 입력.
- **수리비 자동 계산:** 수리 항목 별 단가와 수량을 곱한 금액을 합산하여 총 수리비 자동 계산.
- **수리 내역 수정:** 수리비 확정 전까지 수리 내용과 항목 별 금액을 수정.
- **수리비 확정:** 담당 수리 기사가 최종 수리 내역과 비용을 확정하고 결제 도메인에 청구 금액 전달.
- **확정 수리비 변경 제한:** 결제 금액과 수리비의 정합성을 유지하기 위해 확정 이후 일반적인 수정 제한.
- **수리 상세 내역 조회:** 수리 항목, 단가, 수량, 총 수리비 및 수리 결과 조회.
- **제품 별 과거 수리 이력 조회:** 동일 고객 또는 동일 제품의 이전 수리 내역을 확인하여 반복 고장 분석 지원.

### 1.2.8 가상계좌 결제 및 입금 관리 (Payment & Deposit)

- **수리비 청구 정보 생성:** 수리비 확정 시 A/S 접수번호, 고객, 확정 수리비 및 결제 상태를 포함하는 결제 정보 생성.
- **고객 입금 안내:** 가상계좌 발급 후 고객 또는 기업 고객 담당자에게 입금 정보 SMS 발송.
- **수동 입금 완료 처리:** 권한 있는 업체 관리자가 입금 내역을 확인하여 수동으로 입금 완료 처리하고 처리자, 일시 및 사유 기록.
- **결제 상태 관리:** 입금대기, 입금완료, 만료, 실패 등 결제 상태를 관리하고 허용되지 않은 상태 변경 차단.
- **미입금 내역 조회:** 업체 관리자와 접수 담당자가 미입금 A/S 건의 청구 금액, 입금 기한 및 경과 기간 조회.
- **결제 및 입금 처리 이력 관리:** 가상계좌 발급, 웹훅 처리, 수동 입금 확인 및 상태 변경 이력 저장.

### 1.2.9 배송 및 제품 반환 관리 (Shipping & Delivery)

- **배송 정보 생성:** 수리비 입금 완료 후 배송대기 상태의 A/S 요청에 대한 배송 정보 생성.
- **배송지 및 수령인 관리:** A/S 접수 시 입력한 배송지와 수령인 정보를 확인하고 발송 전 수정.
- **택배사 및 운송장번호 등록:** 접수 담당자가 택배사와 운송장번호를 입력하여 배송 정보 관리.
- **배송 상태 관리:** 배송대기, 배송 중, 배송 완료 등의 상태를 관리하고 배송 시작 및 완료 일시 기록.
- **방문 수령 처리:** 고객이 직접 방문하여 제품을 수령하는 경우 수령 확인 후 A/S 완료 처리.
- **배송 시작 SMS 연계:** 배송 시작 시 고객 또는 기업 고객 담당자에게 택배사와 운송장번호 안내.
- **배송 상태 변경 이력 관리:** 배송 상태 변경자, 변경 일시 및 변경 전후 상태 기록.

### 1.2.10 SMS 알림 및 발송 이력 관리 (SMS & Notification)

- **A/S 접수 알림:** 접수 완료 시 고객 연락처로 접수번호 및 접수 내용을 포함한 SMS 발송.
- **가상계좌 발급 알림:** 수리비 확정 및 가상계좌 발급 시 고객에게 은행명, 계좌번호, 입금 금액 및 입금 기한 안내.
- **입금 완료 알림:** 입금 완료가 확인되면 고객에게 입금 확인 및 제품 반환 준비 안내.
- **배송 시작 알림:** 제품 배송 시작 시 수령인에게 택배사 및 운송장번호 안내.
- **A/S 완료 알림:** 배송 또는 방문 수령이 완료되면 최종 A/S 처리 완료 안내.
- **외부 SMS API 연동:** SMS 발송 서비스 API를 연동하여 메시지 발송 요청 및 결과 수신.
- **알림 메시지 자동 생성:** 알림 유형에 따라 접수번호, 고객명, 입금 금액, 계좌번호 및 운송장번호 등을 자동 적용.
- **SMS 발송 이력 관리:** 수신번호, 알림 유형, 발송 일시, 발송 상태 및 실패 사유 저장.
- **SMS 중복 발송 방지:** 동일 업무 이벤트의 중복 처리 시 불필요한 메시지 반복 발송 차단.
- **SMS 발송 실패 대응:** 외부 SMS 서비스 장애가 발생해도 A/S 접수, 결제 및 배송의 핵심 업무 처리는 유지.
- **수신번호 개인정보 보호:** SMS 발송 이력 조회 시 권한에 따라 수신번호 마스킹 처리.

### 1.2.11 업체별 대시보드 및 운영 통계 (Dashboard & Statistics)

- **운영 대시보드:** 관리자가 접수대기, 수리 중, 입금대기, 배송대기 및 완료 건수를 통합 조회.
- **월별 A/S 접수 및 완료 통계:** 지정 기간의 접수 건수와 완료 건수를 집계하여 추이 차트 제공.
- **A/S 진행 상태별 통계:** 상태별 업무 건수를 집계하고 비율 및 현황을 시각화.
- **수리 기사별 업무 실적:** 기사별 배정 건수, 수리 완료 건수 및 진행 중 건수 조회.
- **제품 모델별 A/S 발생 통계:** 제품 모델별 접수 건수를 집계하여 고장 접수가 많은 제품 확인.
- **개인·기업 고객별 A/S 통계:** 고객 유형별 접수 건수 및 완료 건수를 비교 조회.
- **고객별 A/S 이용 현황:** 고객별 누적 접수 건수, 완료 건수 및 수리 이력 조회.
- **결제 및 미입금 통계:** 입금 완료 금액, 미입금 금액 및 미입금 건수 집계.
- **A/S 평균 처리 기간 분석:** 접수부터 완료까지의 소요 기간을 계산하여 평균 처리 기간 제공.
- **기간 및 조건별 필터링:** 조회 기간, 제품 모델, 담당 기사, 고객 유형 및 A/S 상태별 통계 필터링.
- **통계 시각화:** 막대그래프, 선그래프 및 원형 차트 등을 활용한 운영 지표 표시.

## 1.3 비기능 요구사항 및 기술 스택

### 1.3.1 시스템 아키텍처 및 기술 스택

- **백엔드 코어:** Java, Spring Boot, Gradle
- **영속성 및 ORM:** Spring Data JPA, Hibernate, MyBatis(복잡한 조회 및 통계 쿼리)
- **데이터베이스:** MySQL
- **보안 및 인증:** Spring Security, JWT 기반 인증 및 역할 기반 접근 제어(RBAC)
- **외부 결제 연동:** Toss Payments API(테스트 환경, 가상계좌)
- **SMS 연동:** 외부 SMS 발송 API
- **배송 연동:** 모의 배송 시스템 및 테스트 웹훅
- **주소 검색:** 주소 검색 API
- **엑셀 처리:** Apache POI 기반 고객 데이터 일괄등록
- **프론트엔드:** React 기반 SPA, RESTful API 통신
- **컨테이너:** Docker, Docker Compose
- **CI/CD:** Github Action 기반 빌드 및 배포 자동화
- **클라우드 인프라:** AWS EC2 및 프로젝트 배포 환경에 필요한 클라우드 서비스
- **API 문서화:** OpenAPI/Swagger 기반 API 명세 관리
- **테스트:** JUnit 5, Spring Boot Test 및 통합 테스트

### 1.3.2 데이터 정합성 및 트랜잭션 관리

- **A/S 상태 전이 정합성:** 현재 상태와 선행 업무 조건을 검증하여 허용되지 않은 상태 변경 차단.
- **수리비 및 결제 금액 정합성:** 수리비 확정 후 결제 요청 금액과 내부 청구 금액의 일치 여부 검증.
- **트랜잭션 경계 관리:** 수리비 확정, 결제 정보 생성, 입금 완료 및 A/S 상태 변경 등 연관 데이터 변경을 적절한 트랜잭션으로 처리.
- **웹훅 멱등성 보장:** PG 입금 이벤트와 배송 이벤트의 중복 수신에 대비하여 동일 이벤트가 여러 번 처리되지 않도록 제어.
- **동시성 제어:** 동일 A/S 요청에 대한 중복 기사 배정, 수리비 확정 및 입금 완료 처리 시 데이터 충돌 방지.
- **DB 무결성 제약조건:** 외래 키, 유니크 제약조건 및 NOT NULL 제약조건을 활용하여 데이터베이스 수준의 정합성 확보.
- **외부 API와 DB 트랜잭션 분리:** 외부 서비스의 응답 지연이나 장애가 데이터베이스 트랜잭션을 장시간 점유하지 않도록 설계.
- **업무 이력 보존:** A/S 상태, 담당 기사, 수리비 및 결제 상태의 주요 변경 이력 기록.

### 1.3.3 성능 및 데이터베이스 최적화

- **목록 조회 페이지네이션:** 고객, 제품, A/S 접수, 결제 및 배송 목록에 페이지네이션 적용.
- **검색 조건 기반 인덱스 설계:** 업체 ID, 접수번호, 고객 ID, A/S 상태 및 접수일 등을 기준으로 인덱스 구성.
- **복합 인덱스 활용:** 업체별 데이터 조회가 빈번한 특성을 고려하여 company_id와 주요 검색 조건을 결합한 복합 인덱스 검토.
- **JPA N+1 문제 방지:** 연관 데이터 조회 시 Fetch Join, EntityGraph 및 DTO 직접 조회 등을 상황에 맞게 활용.
- **복잡한 통계 쿼리 분리:** 다중 테이블 집계와 통계 조회는 필요에 따라 MyBatis 기반 SQL로 구현.
- **엑셀 일괄등록 성능 관리:** 대량 고객 데이터 등록 시 파일 크기 제한, 데이터 검증 및 배치 단위 저장 등을 적용.
- **SQL 실행 계획 분석:** 주요 고객 검색, A/S 목록 및 통계 쿼리의 실행 계획을 확인하고 인덱스 및 쿼리 구조 최적화.

### 1.3.4 보안 및 접근 제어

- **역할 기반 인가:** SUPER_ADMIN, COMPANY_ADMIN, RECEPTIONIST, TECHNICIAN 역할에 따른 API 접근 제어.
- **다중 역할 지원:** 한 직원이 접수 담당자와 수리 기사 권한을 동시에 보유할 수 있도록 구성.
- **업체별 접근 권한 검증:** 사용자 소속 업체와 요청 대상 데이터의 소유 업체가 일치하는지 확인.
- **서버 측 권한 재검증:** 프론트엔드 메뉴 접근 제한과 별개로 중요 API에 대한 서버 측 인가 검증.
- **민감정보 보호:** 비밀번호, 고객 연락처, 주소, PG 인증키 및 외부 API 비밀정보 보호.
- **환경변수 기반 설정 관리:** 데이터베이스 접속 정보, JWT 서명키 및 외부 API 인증 정보를 소스 코드에서 분리.
- **주요 관리자 업무 감사:** 업체 계정 비활성화, 직원 역할 변경, 수동 입금 확인 등의 주요 업무 처리 이력 기록.

### 1.3.5 장애 대응 및 외부 시스템 연동 안정성

- **PG 웹훅 장애 대응:** 입금 웹훅 처리 실패 시 오류를 기록하고 PG 결제 상태 재조회 기능을 통해 정합성 확인.
- **외부 API 타임아웃 관리:** PG 및 SMS API 요청에 연결·응답 타임아웃 설정.
- **SMS 장애 격리:** SMS 발송 실패가 정상적으로 완료된 A/S 접수나 결제 업무를 취소하지 않도록 처리.
- **웹훅 중복 및 순서 검증:** 동일 이벤트의 중복 처리와 이전 상태 이벤트로 인한 잘못된 상태 변경 방지.
- **공통 예외 응답:** 인증 실패, 권한 부족, 입력값 검증 오류 및 서버 장애에 대한 일관된 API 오류 응답 제공.
- **운영 로그 및 추적:** A/S 접수번호, 결제 식별자 및 업체 ID를 활용하여 주요 업무 처리 흐름 추적.

### 1.3.6 배포 및 협업 환경

- **Docker 기반 환경 구성:** 백엔드 애플리케이션과 MySQL을 컨테이너 기반으로 구성하여 개발 환경 일관성 확보.
- **CI/CD 파이프라인:** GitHub 저장소의 코드 변경을 기반으로 빌드, 테스트 및 배포 과정 자동화.
- **환경별 설정 분리:** 로컬 개발 환경과 배포 환경의 데이터베이스 및 외부 API 설정 분리.
- **GitHub 협업 프로세스:** 기능별 브랜치, Pull Request 및 코드 리뷰를 통한 팀 단위 개발.
- **API 명세 표준화:** 프론트엔드와 백엔드 간 요청·응답 DTO, 오류 코드 및 인증 방식을 문서화.
- **핵심 업무 통합 테스트:** 고객 등록 → A/S 접수 → 기사 배정 → 수리비 확정 → 가상계좌 발급 → 입금 확인 → 배송 완료까지의 업무 흐름 검증.
