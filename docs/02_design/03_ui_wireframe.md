## 1. 화면 설계

---

### 1.1 화면 설계 개요

---  

#### 1.1.1 화면 설계 목적

FixGo는 사자전자 스마트폰 및 노트북 제품의 A/S 접수부터 점검, 견적 승인, 수리, 결제 및\
제품 반환까지의 전 과정을 통합 관리하는 반응형 SPA 기반 웹 시스템이다. 직원의 고객·제\
품·수리 이력 관리, 수리기사의 업무 처리, 관리자의 운영 현황 모니터링을 지원하며, 고객 포\
털과 이메일 안내를 통해 고객의 진행 확인 및 견적 승인·결제를 지원한다.

---

#### 1.1.2 공통 UI 구성 및 디자인 규칙

- 직원 화면은 왼쪽 사이드바, 상단 화면 제목·로그인 사용자 정보, 본문으로 구성한다. 사\
  용자 이름으로 마이페이지에 이동하며 로그아웃을 제공한다.

- 사이드바는 역할별 접근 메뉴를 구분하고 현재 메뉴를 강조한다.

- 목록은 검색 및 필터 영역, 데이터 테이블, 페이지네이션으로 구성한다. 기본 페이지 크\
  기는 20건이며 처음·이전·번호·다음·마지막으로 이동한다.

- 정렬 가능한 열 제목을 다시 클릭하면 오름차순/내림차순을 전환한다. 검색·필터 변경\
  시 해당 목록을 갱신한다.

- 상세 화면은 관련 정보를 카드 또는 구역으로 나누고 항목명과 값을 구분한다. 행 선택으\
  로 상세 페이지 또는 모달을 연다.

- 등록·수정·삭제·완료 처리 버튼은 역할과 업무 상태에 따라 표시한다. 확인이 필요한 동\
  작은 확인 후 실행하며 실패 시 오류를 안내한다.

- 운영 확인 화면은 청색 계열 브랜드 색상과 흰색 카드, 연한 회색 배경을 사용한다. 성공/\
  완료는 녹색, 실패·반려는 오류 색상으로 구분한다.

- 고객 포털은 직원 사이드바 없이 고객용 진행 단계와 현재 업무를 표시한다.

적으로 마이페이지, 비밀번호 변경, 직원 목록·상세 조회를 사용한다.

### 1.3 업무 기능별 상세 화면 설계

화면별로 실제 URL 또는 모달의 진입 위치, 접근 권한, 화면 캡처, 출력 데이터, 입력 데이\
터, 화면 제어 및 동작 규칙을 작성한다.

---

#### 1.3.1 인증 및 계정 관리

##### 1.3.1.1 로그인 (/login)

접근 권한: 직원 공통

<img src="../images/ui-wireframe/page-06-x122.jpg" alt="PDF p. 10 wireframe" width="500">

**출력 데이터 항목 (Output Data)**

- 이메일, 비밀번호 입력란

- 로그인 버튼

- 데모 계정 버튼: 관리자, 접수담당자, 수리기사

- 로그인 실패 시 오류 메시지

**입력 데이터 항목 (Input Data)**

- 이메일

- 비밀번호

- 데모 계정 선택

**화면 제어 및 동작 규칙 (Behavior Rules)**

- 이메일과 비밀번호가 맞으면 역할에 맞는 첫 화면인 A/S 목록으로 이동한다.

- 실패하면 로그인 화면에 머물고 오류를 보여 준다.

- 로그인하지 않은 사용자는 업무 화면으로 들어가지 못한다.

- 데모 계정 버튼은 해당 계정의 이메일과 비밀번호를 입력란에 채운다.

- 이미 로그인한 사용자는 A/S 목록으로 이동한다.

##### 1.3.1.2 마이페이지 및 비밀번호 변경 (/member/me)

- 보증 판정: 1차 판정, 최종 판정, 청구 금액

- 점검 항목, 견적 합계, 보증 무상 금액, 청구 금액

- 수리 프리셋 선택

- 점검 내용

- 고객 과실 여부와 판정 사유

- 점검 중단 사유: 수리 불가 등

- 점검 완료

  은 유상으로 바꿀 수 있고, 사유가 필요하다.

- 무상으로 저장하면 금액은 0원이고 고객 승인 없이 수리 대기로 넘어간다.

- 유상으로 저장하면 견적 승인 대기가 된다.

- 수리 불가 등으로 점검을 중단하면 견적과 수리를 건너뛰고 반환 단계로 간다.

- 점검 기록이 없는 경우 안내 문구를 표시한다.

- 접수 상태에서 점검 시작을 수행한다. 프리셋을 적용하거나 항목을 추가·수정·삭제하고\
  견적 합계를 표시한다.

- 유상 수리 완료는 결제 단계로, 무상 또는 반환 처리 건은 수령 방식에 따른 배송 대기·수\
  령 대기로 이어진다.

- 배송 준비 완료(READY) 상태에서 배송 알림 기능을 사용할 수 있다.

- 배송 알림 버튼 클릭 시 배송 상태를 배송 중(SHIPPING)으로 변경하고 발송 시각을 기\
  록한다.

- 고객 이메일로 배송 시작 안내를 발송한다.

- 배송 안내 이메일에는 택배사, 운송장번호 및 배송 조회 링크를 포함한다.

- 이메일 발송 결과는 이메일 발송 내역에 저장한다.

- 배송 시작 처리 후 변경된 배송 상태와 발송 시각을 배송 목록 및 상세에 반영한다.

- 이미 배송이 시작된 건은 중복으로 배송 시작 처리할 수 없다.

##### 1.3.7.6 배송 조회 및 배송·수령 완료 처리

접근 권한: 관리자 · 접수담당자

<img src="../images/ui-wireframe/page-41-x344.png" alt="PDF p. 41 wireframe" width="68.07%"> <img src="../images/ui-wireframe/page-41-x345.png" alt="PDF p. 41 wireframe" width="27.93%">

**출력 데이터 항목 (Output Data)**

- 접수 정보: 접수번호, 수령인, 수령 방법

- 배송 정보: 택배사, 운송장번호, 현재 배송 상태, 발송 시각

- 배송 조회 결과: 최신 배송 상태 및 배송 완료 여부

- 배송 이력: 배송 단계, 처리 내용, 처리 위치, 발생 일시

- 방문 수령 정보: 수령 상태, 수령 완료 일시

**입력 데이터 항목 (Input Data)**

- 배송 조회 버튼

- 배송 완료 버튼

- 수령 완료 버튼

**화면 제어 및 동작 규칙 (Behavior Rules)**

- 배송 조회: 배송 조회 버튼 클릭 시 등록된 택배사 코드와 운송장번호를 이용하여 스마트\
  택배(SweetTracker) API를 호출하고, 최신 배송 상태 및 상세 배송 이력을 갱신한다.

- 자동 배송 상태 갱신: Spring Scheduler를 통해 배송 중(SHIPPING)인 배송 내역을\
  매일 오전 10시에 자동으로 조회하고 배송 상태 및 배송 이력을 갱신한다.

- 자동 배송 완료: 스마트택배 API 조회 결과가 배송 완료(complete = true, level = 6)\
  인 경우 배송 상태를 배송 완료(DELIVERED)로 자동 변경한다.

- 수동 배송 완료: 배송 중(SHIPPING)인 건은 담당자가 배송 완료 버튼을 클릭하여 수동\
  으로 배송 완료 처리할 수 있다.

- 방문 수령 완료: 방문 수령 대기 상태에서 고객이 제품을 수령하면 수령 완료 버튼을 클\
  릭하여 방문 수령 완료(PICKED_UP)로 변경하고 수령 완료 일시를 기록한다.

- A/S 상태 연계: 자동 또는 수동 배송 완료 및 방문 수령 완료 처리 시 해당 A/S 접수 상\
  태를 완료(COMPLETED)로 변경한다.

- 상태 변경 이력 관리: 변경 전 상태, 변경 후 상태, 변경 일시, 변경자 및 변경 사유를 A/S\
  상태 변경 이력에 저장한다.

- 중복 처리 방지: 동일한 배송 이벤트는 고유 키(eventKey)를 기반으로 중복 저장을 방\
  지하며, 이미 완료된 배송 및 방문 수령 건은 중복으로 완료 처리할 수 없다.

- 조회 실패 처리: 배송 조회 실패 시 오류 내용을 기록하고 기존 배송 상태를 유지한다. 특\
  정 배송 건의 자동 조회가 실패하더라도 나머지 배송 건의 조회는 계속 진행한다.

- 화면 갱신: 배송 조회 및 완료 처리 결과를 배송 목록, 배송 상세 및 A/S 접수 상세에 반\
  영한다.

**화면 제어 및 동작 규칙 (Behavior Rules)**

- 행에서 들어온 직원의 정보와 최근 배정 접수를 보여 준다.

- 관리자가 역할을 바꾸거나 상태를 바꾸면 바로 저장한다.

- 삭제는 확인 후에만 실행하고, 계정 상태를 삭제로 바꾼다.

- 수리기사에게 끝나지 않은 A/S가 있으면 역할 변경, 비활성, 삭제를 할 수 없다.

- 로그인한 본인의 역할이나 상태를 바꾸거나 삭제하면 로그아웃한다.

- 접수담당자와 수리기사는 상세를 볼 수 있고, 수정·삭제·역할 변경은 관리자만 한다.

- 최근 배정 목록의 접수번호를 누르면 해당 A/S 상세로 이동한다.
